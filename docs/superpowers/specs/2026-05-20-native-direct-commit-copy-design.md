# Native Direct Commit Copy Design

## Problem

ContinuityDB now supports cursor-based commit export, validated import, dry-run validation, CLI paging, and import summaries. Embedders still need to manually compose `source.export_commits(...)` and `target.import_commit_batch_with_summary(...)` for the common local sync case where both databases are open in-process. That is easy to get wrong and forces applications to learn more of the backup implementation than necessary.

## Options Considered

1. Add a high-level `copy_commits_from` API that composes export and import directly.
2. Add a larger sync subsystem with conflict skipping, retry policies, and checkpoint state.
3. Leave direct sync composition to callers.

Option 1 is the right next slice. It provides a real embeddable sync primitive while preserving current deterministic semantics: exported commit pages are imported exactly, duplicate target commits still fail, and cursor metadata is returned to callers.

## Design

Add a generic API on `ContinuityDb<K>`:

```rust
pub fn copy_commits_from<S: StorageKernel>(
    &mut self,
    source: &ContinuityDb<S>,
    lookup: CommitManifestLookup,
) -> Result<CommitImportSummary, ContinuityError>
```

The method:

1. Calls `source.export_commits(lookup)`.
2. Calls `self.import_commit_batch_with_summary(batch)`.
3. Returns the import summary, including `imported_commits` and `next_after`.

This is intentionally not a conflict-resolving sync engine. It is a deterministic commit replay helper. If the target already has an exported commit or cell, the existing import validation fails before mutation. If the source cursor is unknown, the existing export path returns `CommitNotFound`.

## Data Flow

```text
source ContinuityDb<S>
  export_commits(lookup)
    -> CommitExportBatch
target ContinuityDb<K>
  import_commit_batch_with_summary(batch)
    -> CommitImportSummary
```

No file I/O, no envelope encoding, and no CLI changes are required for this slice. The CLI can continue using file envelopes; future work may add a command that uses direct copy for two local stores.

## Error Handling

- Unknown source cursor returns `KernelError::CommitNotFound`.
- Duplicate target commit returns `KernelError::DuplicateCommit`.
- Duplicate target cell returns `KernelError::DuplicateCell`.
- Malformed exported slices should not occur through this path because the batch is generated by `export_commits`, but the existing import validator still runs.
- Empty pages return `CommitImportSummary { imported_commits: 0, next_after: None }`.

## Tests

- Copying one limited page from a source into an empty target imports one commit and returns the source page cursor.
- Copying the next page with the previous cursor imports the second commit.
- Copying from an empty source returns zero imports and no cursor.
- Copying a commit into a target that already has the same commit fails without mutating the target beyond its existing commit.
- Copying from an unknown source cursor returns `CommitNotFound`.
